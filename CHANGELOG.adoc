[#v0_66_0]
== pakakeh.go v0.66.0 (2026-07-06)

This release has major refactoring on [lib/sql] and one breaking changes in
the [lib/time.Scheduler].

**🪵 lib/sql: remove field ListHolder in Meta**

Instead of storing the list of holder, generates them when needed,
especially in Holders() and UpdateFields() methods.

**🪵 lib/sql: remove the Index field from Meta**

Previously, the Index field is used to track the numeric holder for
PostgreSQL driver.
Along the time, we did not have any valid use cases to track it, so we
can safely remove it here.

**🪵 lib/sql: add prefix Bulk to method BindName and BindValues in Meta**

The prefix indicates that those methods are for bulk insert operations.

**🪵 lib/sql: remove the kind field and parameter from Meta**

The original purpose of kind field is to increment the nholder so the
Meta query can generate holder like $1, $2, ... for driver Postgresql.

This changes add BindSelect to differentiate with Bind method for insert
or update so we can remove the kind parameter and field from Meta.

**🪵 lib/time: add method Start to Scheduler**

Previously, the Scheduler automatically started when created
using NewScheduler.
On some cases, we did not want it that way, the Scheduler
should be started explicitly.


**🌱 lib/sql: add methods to generate SQL query**

The Delete, Insert, Select, and Update returns the SQL query for delete,
insert, select, and update statement, respectively.

**🌱 lib/sql: add method BulkInsert**

The BulkInsert method returns the string query for bulk insert.

**🌱 lib/sql: add method BindOrderBy to Meta**

The BindOrderBy method adds the column name and their order for
generating SELECT...ORDER BY query.

**🌱 lib/sql: add method BindLimit to set the query limit on select statement**

**🌱 lib/sql: add method BindJoin and BindLeftJoin in Meta**

The BindJoin method adds the JOIN statement for SELECT query, while
BindLeftJoin method adds the LEFT JOIN statement.

**🌱 lib/sql: implements common SQL DML using Meta and Session**

By combining Meta and Session, this package provides functions to execute
SQL delete, insert, select, and update by passing them into function.

The Meta argument generate the DML query based on pre-defined bindings,
while the Session argument execute the query.

**🌼 lib/time: use [rand.Int] package to generate ID instead of NowFunc**

In a module that override NowFunc() for testing, the returned time will
always the same, and it would panic after 5 attempts.

Instead of using NowFunc generate id using [crypto/rand.Int].

**🌼 lib/uuidv7: use binary.NativeEndian to convert random bytes to uint64**

Using binary.Uvarint does not read the full bytes and cause many zeros
on generated UUID.


[#v0_65_0]
== pakakeh.go v0.65.0 (2026-06-07)

🪵 lib/http: makes the Endpoint.RequestType strict.

Previously, the endpoint ccept any content-type regarding the value
in [Endpoint.RequestType].

This changes make the endpoint become strict, it will reject request if
the Content-Type does not match with registered type.

This is breaking changes.

🌼 lib/systemd: mark daemon build-able only on linux OS.

The other OS will get stub that return nil listener without error.

🌼 lib/os: do not remove the archive/compressed file on success.

Removing a file should be handled by user not a program.

🌼 lib/html: fix NormalizeForID that replace original value.

Turns out modifying slice of byte of string modify the original content of
string itself.
I thought string is immutable.

🌼 lib/time: expose the variable NowFunc.

The NowFunc variable is a function that return the current local time.
It is exposed so that it can be override to mock the current time during
testing.

🌼 lib/uuidv7: allow un-marshaling empty data.

Empty data or empty string "" similar to setting the value to nil.

🌼 lib/http: set content-type in DefaultErrorHandler based on ResponseType.

Previously, any error handled by DefaultErrorHandler always response
with content-type JSON with predefined message format.

This changes it to set response content-type based on registered
[Endpoint.ResponseType].

For [ResponseTypeBinary], [ResponseTypeHTML], [ResponseTypePlain], or
[ResponseTypeXML] it will write the error message in the body as plain
text.
For [ResponseTypeJSON] it use the previous format.

🌼 lib/time: implement internal worker for managing ticker in schedulers.

The worker define internal worker for [time.Scheduler].
Its run a ticker, rounded by minute, that publish the current [time.Time]
to all subscribers.

The original idea is to fix the Scheduler not running as scheduled when
the host system is suspended or sleep.

🌼 lib/time: replace Scheduler ticker with worker

There is a case where a program that use Scheduler with schedule set
to daily at 00:00 is never run as scheduled.
The cause was the host that run the program is being suspended or sleep
on OS level.
The program is still running after wake up but the schedule is delayed
based on how long the host OS suspened.
If its suspended for 3 hours, then the scheduler will run at 03:00.

The fix is by running an internal worker that run a ticker.
Scheduler that register to this worker, will receive an instance of
current time in UTC every minute, which they will use to compare with
their next schedule.

=== lib/http

🪵 Return an error on `UnmarshalForm`.

Previously, if UnmarshalForm cannot set the value of field, it will
continue to the next field without returning any error.

[#v0_63_0__lib_sql]
=== lib/sql

🪵 Refactoring the `Meta.BindWhere` method.

Changes the BindWhere parameters from two to four.
The first parameter is the OR/AND logic.
The second parameter is the column name.
The third parameter is the operator like "=", "!=".
The fourth parameter is the value.

This is to prevent missing logic and operator, which happen frequently.

🪵 The `JoinValues` function has been removed in favor of `slices.Concat`.

🌱 Add method `Client.Meta`.
The Meta method returns new instance of [Meta] based on the current
client driver and kind argument.

🌱 Support generating query for bulk insert.

Given the following insert query

	INSERT INTO (x,y) VALUES ($1, $2), ($1, $3);

The new method `BindName("x", false)` will bind column name "x" with the
same values for each subsequent calls to `BindValues`; while
`BindName("y", true)` bind the column name "y" with unique values for
each subsequent calls to `BindValues`.

The new method `BindValues` bind the values for each record.

The new method `BulkHolders` returns the query string, for example
"($1,$2),$($1,$3)".

The new method `InsertValues` returns the list of values for executing
insert statement.

[#v0_63_0__lib_text_diff]
=== lib/text/diff

The `diff` package has been receive major refactoring to support unified
diff and to clean up the old codes.

🪵 The first refactoring is to use local `Line` type instead from `lib/text`
package.
The reason for refactoring is we will add more fields to the Line type
to handle unified diff.

In the `ParseLines`, we changes the line number to start from 1, to make it
consistent with `ReadLines` and file line numbering.
This causes a lot of changes in the expectation files in the testdata.

🪵 The function `IsEqual` has been removed in favor of `bytes.Equal`.

🪵 The `LineChanges` type has been removed.

Defining `[]T` as new type does not help on readability only make it
confusing for future maintenances.

🪵 The type `LineChange` has been renamed to `LineChunk`.
In the struct Data we also rename field Changes to LineChunks.

🪵 The `LevelWords` constant has been renamed to `LevelChunks`.
Using Words seems like misleading since we capture the characters
difference, not a word as in human language.

🌱 Implements unified diff.

Unified diff is the common diff output that we see, mostly in git diff
output.

The following new APIs are ready to use,

- `Unified()` compare two stream of bytes and returns new instance of
  `diff.Data`.
- `Data.WriteUnified()` write the diff as unified format into argumen type
  `io.Writer`.

[#v0_63_0__lib_uuidv7]
=== lib/uuidv7

🪵 The `UUIDv7` type renamed to `UUID` for simplicity since the package name
already have v7.

🪵 The `Now` and `Rand` functions renamed to `NowFunc` and `RandFunc`.
Using `Func` suffix in the function variable is common coding style in Go,
which makes the exported variables easy to understand.

🌱 The UUID now have method `IsEqual` to simplify checking for equality in
if-condition.

🌼 During Unmarshaling, if the UUID value being decoded is not valid, don't
changes the current value.
This fix the value that changes only half of the UUID part (high part) but
not the other part (the low).

🌼 The marshaling and `Value` methods now return nil if ID is zero.

Per RFC 9562 Section 5.9,

  A Nil UUID value can be useful to communicate the absence of any
  other UUID value in situations that otherwise require or use a
  128-bit UUID.
  A Nil UUID can express the concept "no such value here".
  Thus, it is reserved for such use as needed for
  implementation-specific situations.

In case of SQL, the Value method should return nil if ID is zero.

==== 🪵 lib/dns: refactoring DoT and DoH to use address instead of port

Using port makes the IP address of DNS-over-TLS (DoT) and DNS-over-HTTPS
(DoH) listen on the same address with UDP.
If we set `ListenAddress` to `0.0.0.0` and TLS termination is handled
by proxy, this cause DoT and DoH will also listen on all
addresses (the ports open to public).


[#v0_62_0__lib_http]
=== lib/http

==== 🌱 Add BasePath to the ServerOptions

The BasePath allow server to serve HTTP from custom prefix, other than "/".

Each request that server received will remove the BasePath first
from the [http.Request.URL.Path] before passing to the handler.
Each redirect that server sent will add the BasePath as the prefix
to redirect URL.

Any trailing slash in the BasePath will be removed.

==== 🌱 Implement server auto shutdown when idle

In the `ServerOptions`, we add option `ShutdownIdleDuration` when set to
non-zero value it will start a timer.
When the timer expired, the server will stop accepting new connection and
then shutting down.

This allow de-activating HTTP server when no connections received after
specific duration to reduce the system resources.

==== 🌼 lib/http: fix possible data race in SSE connection

When server's handler call Write or WriteRaw, there is possibility that
the worker for keeping the connection alive also call Write at the same
time, which cause the data race.

[#v0_61_0__lib_dns]
=== lib/dns

==== 🌼 lib/dns: use separate ServeMux for handling DoH

Using the [http.DefaultServeMux] will cause panic when the server
restarted manually using Stop-Start flow.

==== 🌼 lib/dns: skip caching empty answer only for query type A

Previously, we did not store response with empty RR answer for all record
types.
Meanwhile, some domains still does not have AAAA(28) and HTTPS(65) records
set, but browser will requesting them.
So, to minimize traffic for those query we skip caching only for query type
A and cache the rest of types.

==== 🌼 lib/dns: remove DebugLevelDNS

The DebugLevelDNS log the error on DNS level, for example empty answer,
error on name, class not implemented, refused; which is now on by
default.

==== 🌱 lib/dns: add option to set hook on server when receiving answer

The hook function, OnAnswerReceived, will be triggered when server
receive valid answer but before its put to caches.

==== 🌱 lib/dns: add method to set TTL on Message

The SetTTL method set all RRs answer time to live.

==== 🌼 lib/dns: print the answer TTL in DebugLevelCache

The log level cache changed to the following format,

----
... {MSG_ID QNAME TYPE TTL} ...
----

where MSG_ID is the message ID, QNAME is the question name, TYPE is the
type of question, and TTL is the time-to-live of the answer.

==== 🌼 lib/dns: simplify log message for DebugLevelCache

For each logged request, there should be one line of response logged,
success or fail.

This changes remove redundant log "^" (request forwarded) and
"~" (answer is expired).
The final log would be only "+" (new answer cached), or "#" (answer
updated), or "!" (error).

==== 🌼 lib/dns: increase the client default timeout from 6 to 60 seconds

The 6 seconds timeout will works only on fast, stable connection.

On some environment with bad network connection, it will cause I/O timeout
during recv and this affect the whole internet connections, like
browsing.
Since the browser wait for domain to be resolved but it does
not get the response, it send another query.
The next query also got timeout again.

Increasing to 10-30 seconds also does not help on that environment.
After some tests, 60 seconds is the lower timeout limit that reduce
the I/O timeout.

It is better that we receive the response and store it to caches, so
the next query can be handled quickly, rather than timeout and retrying
with the same error.

This method accept second paramter "format", default to
'%h,%at,%an,%ae,%s' which print short hash, author commit timestamp,
author name, author email, and subject; respectively separated by comma.

[#v0_61_0__lib_http]
=== lib/http

==== 🪵 lib/http: change HandleFS redirect status code to 301

According to MDN
https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Redirections[Redirections in HTTP]
the HTTP status 302 Found use case is for "Web page (that) is temporarily
unavailable for unforeseen reasons.".

This probably to re-route the page until the original page is fixed.
While HTTP status 301 is for "Reorganization of a website.".

Since the redirection in HandleFS only happen when user access directory
without slash, we should make it permanent.

==== 🌼 lib/http: set HandleFS to always end with slash "/"

Previously, if request to directory does not end with "/", the HTTP
server will return the index.html of that directory.
This cause relative link inside the index.html broken when visited from
browser.

This changes make the request to directory always end with "/" by
redirecting the request with status 303 Found.

==== 🌱 lib/http: add field Listener to ServerOptions

The field Listener allow user to pass [net.Listener] for accepting new
connection using [http.Serve] or [http.ServeTLS].

==== 🪵 lib/http: add second return value, statusCode, to FSHandler

Non-zero status code indicates that the function already response
to the request, and the server will return immediately.

Zero status code indicates that the function did not process the request,
it is up to server to process the returned node `out`.
